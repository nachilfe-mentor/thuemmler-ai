JewelryStore & ShoeStore Schema Markup: JSON-LD für Juweliere und Schuhgeschäfte

Wie du JewelryStore und ShoeStore Schema Markup korrekt implementierst — mit vollständigen JSON-LD-Codebeispielen, allen relevanten Properties und den wichtigsten Unterschieden zwischen Juwelieren, Uhrenhandlungen und Schuhgeschäften.

30. April 2026 · ca. 9 min Lesezeit · Thümmler AI GmbH

Juweliergeschäfte und Schuhgeschäfte sind zwei sehr unterschiedliche Branchen — verbunden durch einen gemeinsamen SEO-Hebel: das richtige Schema Markup. Mit JewelryStore und ShoeStore als strukturierte Daten kannst du Google präzise mitteilen, welche Art von Geschäft du betreibst, und damit Öffnungszeiten, Bewertungssterne und das Knowledge Panel in den Suchergebnissen aktivieren.

Dieser Artikel zeigt beide Schema-Typen im Detail — von der Typauswahl über Pflichtfelder bis zu den spezifischen Properties, die für Juweliere und Schuhläden besonders relevant sind. Für eine schnelle JSON-LD-Generierung ohne Programmierkenntnisse eignet sich unser ClothingStore, ShoeStore & JewelryStore Schema Generator.

JewelryStore und ShoeStore in der Schema-Hierarchie

Beide Typen erben von Store, das selbst ein Untertyp von LocalBusiness ist:

Thing → Organization → LocalBusiness → Store → JewelryStore
Thing → Organization → LocalBusiness → Store → ShoeStore

Durch diese Hierarchie erben beide Typen alle Properties von Store, LocalBusiness und Organization — du hast also ein breites Spektrum an Feldern zur Verfügung.

Wann JewelryStore, wann ShoeStore?

JewelryStore: Juweliere, Goldschmiede, Uhrenhandlungen, Schmuckatelier, Accessoires-Boutiquen mit Schmuck-Schwerpunkt. ShoeStore: Schuhfachgeschäfte, Schuhketten, Orthopädie-Schuhhändler, Sneaker-Shops. Kombiniert (["JewelryStore", "ShoeStore"]) nur wenn tatsächlich beides angeboten wird.

Pflichtfelder und empfohlene Properties

Für eine vollständige Local Business Darstellung in Google empfehlen sich folgende Properties:

  • @type — Typ des Geschäfts
  • name — Offizieller Geschäftsname
  • address — PostalAddress mit Straße, PLZ, Stadt, Land
  • telephone — Telefon mit Ländercode
  • url — Website-URL
  • openingHoursSpecification — Strukturierte Öffnungszeiten

Zusätzlich empfohlen:

  • image — Foto des Geschäfts oder Schaufensters
  • description — Sortimentsbeschreibung
  • geo — GPS-Koordinaten für "in der Nähe"-Suchen
  • aggregateRating — Bewertungssterne
  • priceRange — Preissegment (besonders für Juweliere relevant)
  • currenciesAccepted — Akzeptierte Währungen
  • sameAs — Google Maps, Instagram, Facebook

JSON-LD-Beispiel: JewelryStore (Juwelier / Goldschmied)

Das folgende Markup ist für ein Juweliergeschäft optimiert. Besonders das priceRange-Feld ist bei Juwelieren wichtig — es hilft, Kunden mit dem passenden Budget anzusprechen:

  "geo": {
    "@type": "GeoCoordinates",
    "latitude": 48.1374,
    "longitude": 11.5755
  },
  "openingHoursSpecification": [
    {

Besonderheiten für Juweliere: Kombination mit ClothingStore

Viele Juweliergeschäfte verkaufen nicht nur Schmuck, sondern auch Accessoires, Uhren und manchmal sogar Lederwaren. In diesen Fällen lohnt sich ein kombinierter Typ:

{
  "@context": "https://schema.org",
  "@type": ["JewelryStore", "Store"],
  "name": "Juwelier & Accessoires Boutique Maier",
  ...
}

Eine Kombination mit ClothingStore ist möglich, wenn ein bedeutender Teil des Sortiments Kleidung oder Mode-Accessoires umfasst. Unser ClothingStore, ShoeStore & JewelryStore Generator unterstützt alle drei Typen einzeln oder kombiniert.

Öffnungszeiten und Sonderöffnungszeiten

Juweliere haben oft andere Öffnungszeiten rund um Feiertage (Valentinstag, Weihnachten). Schema.org bietet die validFrom und validThrough-Properties für zeitlich begrenzte Öffnungszeiten:

"openingHoursSpecification": [
  {
    "@type": "OpeningHoursSpecification",
    "dayOfWeek": ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"],
    "opens": "10:00",
    "closes": "18:30"
  },
  {
    "@type": "OpeningHoursSpecification",
    "dayOfWeek": ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday"],
    "opens": "09:00",
    "closes": "20:00",
    "validFrom": "2026-12-20",
    "validThrough": "2026-12-24"
  }
]

Diese Sonderöffnungszeiten gelten nur im angegebenen Zeitraum. Mehr Details zu Öffnungszeiten-Spezifikationen erklärt unser Artikel zu OpeningHoursSpecification Schema Markup.

priceRange: Preiskommunikation im Schema

Die priceRange-Property ist für JewelryStore besonders relevant, da Juweliere in sehr unterschiedlichen Preissegmenten agieren. Google zeigt die Preisklasse in der Knowledge Card an:

  • "€" — Budget-Segment (Modeschmuck, Accessoires)
  • "€€" — Mittleres Segment (Silberschmuck, Einstiegs-Uhren)
  • "€€€" — Gehoben (Goldschmuck, Designer-Uhren, Diamanten)
  • "€€€€" — Luxussegment (Haute Joaillerie, Prestige-Uhrenmarken)

Der Wert ist ein Freitext-String — du kannst auch konkrete Preise angeben: "ab 29 €" oder "49 € – 2.500 €".

Für Schuhgeschäfte: hasOfferCatalog

Schuhgeschäfte mit verschiedenen Abteilungen (Damen, Herren, Kinder, Sport) können hasOfferCatalog verwenden, um das Sortiment strukturiert zu beschreiben:

"hasOfferCatalog": {
  "@type": "OfferCatalog",
  "name": "Sortimentsübersicht",
  "itemListElement": [
    {
      "@type": "OfferCatalog",
      "name": "Damenschuhe"
    },
    {
      "@type": "OfferCatalog",
      "name": "Herrenschuhe"
    },
    {
      "@type": "OfferCatalog",
      "name": "Kinderschuhe"
    }
  ]
}

Google nutzt diese Information, um das Geschäft bei spezifischen Suchanfragen ("Kinderschuhe Düsseldorf") besser zuzuordnen. Mehr dazu im Artikel zu OfferCatalog Schema Markup.

AggregateRating korrekt ausfüllen

Bewertungssterne sind einer der stärksten Klick-Impulse in den Suchergebnissen. Das aggregateRating-Objekt erfordert Genauigkeit:

"aggregateRating": {
  "@type": "AggregateRating",
  "ratingValue": "4.8",
  "reviewCount": 143,
  "bestRating": "5",
  "worstRating": "1"
}

Nutze den aktuellen Durchschnitt aus Google My Business oder anderen Portalen. Schreibe ratingValue immer als String ("4.8"), reviewCount als Ganzzahl. Eine Anleitung für mehr Bewertungen: Google Bewertungen bekommen.

Häufiger Fehler: Bewertungen erfinden

Google vergleicht Schema-Daten mit realen Bewertungsportalen. Erfundene oder übertriebene Bewertungszahlen führen zur Depriorisierung oder zum Verlust der Rich Result Darstellung. Nutze ausschließlich echte Bewertungsdaten.

Kombination mit Product Schema für Bestseller

Für Juweliere und Schuhläden mit einem Onlineshop oder Produktkatalog lässt sich das Store-Schema mit einzelnen Product-Schemata kombinieren — jeweils auf separaten Produktseiten, nicht auf der Store-Hauptseite:

<!-- Auf der Produktseite eines Trauring-Modells: -->
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Trauringe Klassik 585 Gold",
  "description": "Klassische Trauringe aus 585 Gold, mattiert",
  "brand": {
    "@type": "Brand",
    "name": "Goldmann Eigenproduktion"
  },
  "offers": {
    "@type": "Offer",
    "price": "389",
    "priceCurrency": "EUR",
    "availability": "https://schema.org/InStock"
  }
}

Integration: Wo gehört das JSON-LD hin?

Das Store-Schema gehört auf die Startseite oder die Filialübersichtsseite — nicht auf einzelne Produktseiten. Der Code kommt in den <head>-Bereich:

<head>
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "JewelryStore",
    "name": "Juwelier Goldmann",
    ...
  }
  </script>
</head>

Mehrere JSON-LD-Blöcke pro Seite sind erlaubt — z. B. einen für den Store und einen für die Breadcrumb-Navigation. Mehr zur Implementierung strukturierter Daten findet du in unserem Grundlagenartikel.

Validierung: Schema korrekt prüfen

Nach der Implementierung unbedingt validieren:

  1. Google Rich Results Test — prüft, ob Google das Markup für Rich Results in Betracht zieht
  2. Schema.org Validator — prüft syntaktische Korrektheit
  3. Unser JSON-LD Structured Data Validator — direkter Browser-Check

Checkliste: Schema korrekt implementiert?

  • ✅ @type korrekt gesetzt (JewelryStore oder ShoeStore)
  • ✅ name, address, telephone ausgefüllt
  • ✅ openingHoursSpecification als Array mit @type
  • ✅ ratingValue als String ("4.8"), nicht als Zahl
  • ✅ addressCountry als ISO-Code ("DE")
  • ✅ Telefon mit Ländervorwahl (+49)
  • ✅ geo mit latitude und longitude als Dezimalzahlen
