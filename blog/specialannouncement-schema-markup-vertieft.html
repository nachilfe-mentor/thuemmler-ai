SpecialAnnouncement Schema Markup vertieft: COVID-Properties, Behörden und Multi-Location

📅 6. Mai 2026 ⏱ 12 Min. Lesezeit Schema Markup Tech-SEO Structured Data

Das SpecialAnnouncement Schema Markup wurde ursprünglich im Frühjahr 2020 von Google als Reaktion auf die COVID-19-Pandemie eingeführt — und ist seitdem zum Standardwerkzeug für Organisationen geworden, die zeitkritische Informationen strukturiert an Google kommunizieren müssen. Die Grundlagen kennst du bereits. In dieser vertieften Analyse geht es um die komplexeren Anwendungsfälle: pandemie-spezifische Properties, den richtigen Umgang mit deutschen Behörden-Strukturen, gleichzeitig aktive Mehrfach-Ankündigungen auf einer Domain und die sinnvolle Kombination mit FAQPage Schema.

1. COVID-spezifische Properties im Detail

Google hat für SpecialAnnouncement eine Reihe von Properties eingeführt, die explizit auf Gesundheitsnotfälle und Pandemien zugeschnitten sind. Viele Webmaster kennen nur die Basis-Properties wie name, text und expires. Die spezialisierten COVID-Properties sind jedoch entscheidend für maximale Sichtbarkeit in Gesundheitskontext-Suchen.

Property Typ Beschreibung
diseaseSpread URL Link zu offizieller Seite mit Informationen zur Ausbreitung der Krankheit
diseasePreventionInfo URL oder WebContent Link zu Präventionsmaßnahmen (Hygiene, Abstände, Schutzausrüstung)
getsVaccineAtoZ URL oder WebContent Link zu Impfinformationen: Wer kommt dran, Impfstellen, Anmeldung
newsUpdatesAndGuidelines URL oder WebContent Link zur aktuellen Newsseite/Lageberichten der Organisation
publicTransportClosuresInfo URL oder WebContent Informationen zu Einschränkungen im öffentlichen Nahverkehr
quarantineGuidelines URL oder WebContent Link zu Quarantäne-Regeln und Isolationspflichten
schoolClosuresInfo URL oder WebContent Informationen zu Schulschließungen, Distanzunterricht, Notbetreuung
travelBans URL oder WebContent Link zu Reisebeschränkungen und Einreiseverboten
governmentBenefitsInfo GovernmentService Staatliche Hilfsleistungen: Kurzarbeit, Förderprogramme, Soforthilfen

2. Deutsche Behörden: Gesundheitsamt, Landkreis, Kommunalverwaltung

Für deutsche Behörden gibt es im Schema.org-Ökosystem spezifische Typen, die du kennen solltest. Der Einsatz des richtigen @type für die ausgebende Organisation beeinflusst, wie Google die Vertrauenswürdigkeit der Ankündigung einschätzt.

Welcher Organization-Typ passt zu welcher Behörde?

Behörde Schema.org-Typ Beispiel
Bundesministerium, Landesministerium GovernmentOrganization Bundesgesundheitsministerium
Stadt, Gemeinde, Landkreis GovernmentOrganization Stadt München, Landkreis Ebersberg
Schulen School Gymnasium am Stadtpark
Universitäten CollegeOrUniversity Technische Universität Berlin
Krankenhäuser, Kliniken Hospital Universitätsklinikum Bonn
Amt, Behörde (allgemein) GovernmentBuilding Bürgerbüro Mitte

Das spatialCoverage-Feld: Geographischen Geltungsbereich definieren

Eine besonders wichtige, oft übersehene Property ist spatialCoverage. Sie teilt Google mit, für welches geographische Gebiet die Ankündigung gilt. Das ist besonders für lokale Behörden relevant: Eine Sperrung des Stadtparks in Hamburg ist nicht relevant für Nutzer in München.

"spatialCoverage": [
  {
    "@type": "City",
    "name": "Hamburg",
    "sameAs": "https://www.wikidata.org/wiki/Q1055"
  },
  {
    "@type": "AdministrativeArea",
    "name": "Hamburg-Altona",
    "containsPlace": {
      "@type": "City",
      "name": "Hamburg"
    }
  }
]
Wikidata-IDs nutzen: Für deutsche Städte gibt es auf Wikidata eindeutige IDs. sameAs mit der Wikidata-URL macht deine Ortsangaben maschinell disambiguierbar — besonders wichtig bei häufigen Ortsnamen (z.B. gibt es mehrere Orte namens "Neustadt" in Deutschland).

3. Multi-Location-Ankündigungen richtig strukturieren

Unternehmen mit mehreren Standorten — Restaurantketten, Supermarktfilialisten, Bankfilialen — stehen vor einer besonderen Herausforderung: Wie kommuniziert man eine Ankündigung, die für alle Filialen gilt, aber standortspezifische Informationen enthält (unterschiedliche Öffnungszeiten, unterschiedliche Schließdaten)?

Ansatz 1: Eine zentrale Ankündigung mit mehreren Locations

Wenn alle Standorte identisch betroffen sind, liste sie als Array in announcementLocation:

{
  "@context": "https://schema.org",
  "@type": "SpecialAnnouncement",
  "name": "Geänderte Öffnungszeiten an Feiertagen: Alle Filialen",
  "text": "An den Feiertagen am 29. und 30. Mai 2026 haben alle unsere Filialen von 10 bis 14 Uhr geöffnet. Am 1. Juni bleiben alle Standorte geschlossen.",
  "datePosted": "2026-05-20T09:00:00+02:00",
  "expires": "2026-06-02T00:00:00+02:00",
  "category": "https://www.wikidata.org/wiki/Q7275",
  "announcementLocation": [
    {
      "@type": "Store",
      "name": "Mustermarkt Hamburg-Altona",
      "address": {
        "@type": "PostalAddress",
        "streetAddress": "Altona Hauptstraße 1",
        "addressLocality": "Hamburg",
        "postalCode": "22765",
        "addressCountry": "DE"
      }
    },
    {
      "@type": "Store",
      "name": "Mustermarkt Hamburg-Bergedorf",
      "address": {
        "@type": "PostalAddress",
        "streetAddress": "Bergedorfer Markt 5",
        "addressLocality": "Hamburg",
        "postalCode": "21029",
        "addressCountry": "DE"
      }
    }
  ],
  "author": {
    "@type": "Organization",
    "name": "Mustermarkt GmbH",
    "url": "https://www.mustermarkt.de"
  },
  "url": "https://www.mustermarkt.de/filialinfo/feiertage-2026"
}

Ansatz 2: Separate Ankündigungen pro Standort

Wenn die Ankündigungen je Filiale variieren (unterschiedliche Öffnungszeiten, unterschiedliche Maßnahmen), ist es sauberer, für jede Filiale eine eigene Seite mit eigenem SpecialAnnouncement zu erstellen und auf einer Übersichtsseite alle zu verlinken. Google kann mehrere SpecialAnnouncement-Markups auf einer Domain gleichzeitig verarbeiten.

Warnung: Setze nicht mehrere unabhängige SpecialAnnouncement-Objekte auf eine einzige Seite, wenn sie thematisch nichts miteinander zu tun haben. Google verarbeitet sie technisch zwar, aber für Nutzer ist eine eigene Detailseite pro Ankündigung deutlich sinnvoller — und auch für SEO besser, weil jede Seite ihren eigenen Ranking-Kontext hat.

4. Mehrfache überlappende Ankündigungen auf einer Seite

Manchmal gibt es legitime Gründe, mehrere SpecialAnnouncement-Objekte auf einer einzigen Seite zu platzieren — etwa eine Übersichtsseite "Aktuelle Informationen" mit verschiedenen zeitgleich laufenden Meldungen.

So funktioniert das Array-Pattern

<script type="application/ld+json">
[
  {
    "@context": "https://schema.org",
    "@type": "SpecialAnnouncement",
    "name": "Eingeschränkte Öffnungszeiten: Bürgerbüro Mitte",
    "text": "Das Bürgerbüro Mitte ist vom 12. bis 16. Mai 2026 nur von 9 bis 12 Uhr geöffnet.",
    "datePosted": "2026-05-08T10:00:00+02:00",
    "expires": "2026-05-17T00:00:00+02:00",
    "category": "https://www.wikidata.org/wiki/Q7275",
    "url": "https://www.musterstadt.de/buergerbuero/oeffnungszeiten-mai"
  },
  {
    "@context": "https://schema.org",
    "@type": "SpecialAnnouncement",
    "name": "Straßensperrung: Hauptstraße 12.–20. Mai",
    "text": "Die Hauptstraße (Abschnitt Bahnhofstraße bis Marktplatz) ist vom 12. bis 20. Mai 2026 für den Kraftfahrzeugverkehr gesperrt.",
    "datePosted": "2026-05-08T10:00:00+02:00",
    "expires": "2026-05-21T00:00:00+02:00",
    "category": "https://www.wikidata.org/wiki/Q7275",
    "url": "https://www.musterstadt.de/verkehr/hauptstrasse-sperrung"
  }
]
</script>
Wichtig: Das Array-Pattern (eckige Klammern um die JSON-LD-Objekte) ist die bevorzugte Methode um mehrere Schema-Objekte in einem einzigen <script>-Tag zu übermitteln. Alternativ kannst du mehrere <script type="application/ld+json">-Tags auf derselben Seite verwenden — das ist ebenfalls valide.

5. Aktualisierungsmuster: Wie du laufende Ankündigungen pflegst

Eine der größten Herausforderungen bei SpecialAnnouncement ist das Update-Management. Situationen ändern sich — Maßnahmen werden verschärft, gelockert oder vollständig aufgehoben. Google empfiehlt ein klares Vorgehen:

Pattern A: In-Place-Update mit dateModified

Ändere den text der Ankündigung und aktualisiere dateModified. Die URL bleibt dieselbe. Google erkennt durch den Vergleich von datePublished und dateModified, dass sich die Informationen verändert haben:

{
  "@context": "https://schema.org",
  "@type": "SpecialAnnouncement",
  "name": "Schulschließung Gymnasium am Stadtpark",
  "text": "AKTUALISIERT (15. Mai): Die Schule bleibt nun bis 31. Mai geschlossen. Der Präsenzunterricht beginnt am 1. Juni wieder.",
  "datePosted": "2026-05-08T14:00:00+02:00",
  "dateModified": "2026-05-15T10:00:00+02:00",
  "expires": "2026-06-01T00:00:00+02:00",
  ...
}

Pattern B: Neue Ankündigung + Verweis auf Vorgänger

Bei grundlegenden Lageänderungen ist es sauberer, eine neue Ankündigung zu erstellen und die alte als abgelaufen zu markieren. Verknüpfe die neue Ankündigung über die about-Property mit dem Thema der alten:

{
  "@context": "https://schema.org",
  "@type": "SpecialAnnouncement",
  "name": "Aufhebung der Schulschließung: Gymnasium am Stadtpark",
  "text": "Die am 8. Mai verhängte Schulschließung wird mit sofortiger Wirkung aufgehoben. Ab 18. Mai findet wieder regulärer Präsenzunterricht statt.",
  "datePosted": "2026-05-17T16:00:00+02:00",
  "expires": "2026-05-25T00:00:00+02:00",
  "about": {
    "@type": "Event",
    "name": "Schulschließung Gymnasium am Stadtpark (aufgehoben)"
  },
  ...
}

Abgelaufene Ankündigungen

Wenn das expires-Datum überschritten ist, entfernt Google die Ankündigung automatisch aus den Rich Results. Du musst abgelaufene Seiten nicht manuell löschen — aber es ist gute Praxis, das Schema-Markup nach Ablauf zu entfernen oder die Seite auf 301 auf eine aktuellere Information umzuleiten.

Best Practice: Setze expires immer auf einen konkreten Zeitstempel. Ankündigungen ohne Ablaufdatum werden von Google mit niedrigerem Vertrauen eingestuft, da sie auf schlecht gepflegte Inhalte hindeuten können.

6. FAQ-Integration für SpecialAnnouncement

Eine besonders effektive Kombination ist SpecialAnnouncement zusammen mit FAQPage Schema auf derselben Seite. Die Ankündigung liefert den strukturierten Datensatz für Google, der FAQ-Abschnitt liefert die Antworten auf die häufigsten Nutzerfragen — und Google kann beides als Rich Result gleichzeitig anzeigen.

<!-- SpecialAnnouncement -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "SpecialAnnouncement",
  "name": "Einschränkungen im ÖPNV: Streik 19. Mai 2026",
  "text": "Aufgrund eines ganztägigen Warnstreiks der Busfahrer fahren am 19. Mai 2026 keine Stadtbusse in Musterstadt. U-Bahnen und S-Bahnen verkehren im Normalfahrplan.",
  "datePosted": "2026-05-18T18:00:00+02:00",
  "expires": "2026-05-20T04:00:00+02:00",
  "category": "https://www.wikidata.org/wiki/Q7275",
  "publicTransportClosuresInfo": "https://www.musterstadt-verkehr.de/streik-19-mai",
  "author": {
    "@type": "Organization",
    "name": "Musterstadt Verkehrsbetriebe",
    "url": "https://www.musterstadt-verkehr.de"
  },
  "url": "https://www.musterstadt-verkehr.de/streik-19-mai"
}
</script>

<!-- FAQPage ergänzt die Ankündigung -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Fahren am 19. Mai noch U-Bahnen?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Ja, U-Bahnen und S-Bahnen fahren am 19. Mai 2026 im regulären Fahrplan. Nur die Stadtbusse sind betroffen."
      }
    },
    {
      "@type": "Question",
      "name": "Gibt es Ersatzverkehr für die Busse?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Es gibt keinen organisierten Ersatzverkehr. Wir empfehlen die Nutzung von U-Bahn, S-Bahn, Fahrrad oder PKW."
      }
    },
    {
      "@type": "Question",
      "name": "Ab wann fahren die Busse wieder?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Die Busse nehmen planmäßig am 20. Mai 2026 ab 4:00 Uhr ihren normalen Betrieb wieder auf."
      }
    }
  ]
}
</script>

7. Verknüpfung mit NewsArticle und Event Schema

SpecialAnnouncement ist nicht isoliert — es kann und sollte mit anderen Schema-Typen kombiniert werden um den semantischen Kontext zu maximieren.

SpecialAnnouncement + NewsArticle

Wenn die Ankündigung von einer Redaktion als Artikel aufbereitet wurde, kombiniere beide Schema-Typen. Das ist besonders für kommunale Websites relevant, die Meldungen sowohl als Behördenverlautbarung als auch als News-Artikel veröffentlichen:

{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "SpecialAnnouncement",
      "@id": "https://www.musterstadt.de/news/sperrung-hauptstrasse#announcement",
      "name": "Straßensperrung Hauptstraße 20.–25. Mai",
      "text": "Die Hauptstraße ist aufgrund von Tiefbauarbeiten vom 20. bis 25. Mai voll gesperrt.",
      "datePosted": "2026-05-15T10:00:00+02:00",
      "expires": "2026-05-26T00:00:00+02:00",
      "url": "https://www.musterstadt.de/news/sperrung-hauptstrasse"
    },
    {
      "@type": "NewsArticle",
      "@id": "https://www.musterstadt.de/news/sperrung-hauptstrasse#article",
      "headline": "Vollsperrung Hauptstraße: Was Autofahrer jetzt wissen müssen",
      "datePublished": "2026-05-15T10:00:00+02:00",
      "dateModified": "2026-05-15T10:00:00+02:00",
      "about": {
        "@id": "https://www.musterstadt.de/news/sperrung-hauptstrasse#announcement"
      }
    }
  ]
}

SpecialAnnouncement + Event: Abgesagte Veranstaltungen

Wenn eine Ankündigung eine Veranstaltungsabsage oder -verschiebung betrifft, verknüpfe das SpecialAnnouncement mit dem zugehörigen Event-Schema über about:

{
  "@context": "https://schema.org",
  "@type": "SpecialAnnouncement",
  "name": "Stadtfest 2026 verschoben auf September",
  "text": "Das Stadtfest Musterstadt, ursprünglich für den 15. Juni 2026 geplant, wird auf den 5. September 2026 verschoben.",
  "datePosted": "2026-05-10T12:00:00+02:00",
  "expires": "2026-09-06T00:00:00+02:00",
  "about": {
    "@type": "Event",
    "name": "Stadtfest Musterstadt 2026",
    "startDate": "2026-09-05",
    "endDate": "2026-09-07",
    "eventStatus": "https://schema.org/EventRescheduled",
    "previousStartDate": "2026-06-15",
    "location": {
      "@type": "Place",
      "name": "Marktplatz Musterstadt"
    }
  }
}

Achte auf den eventStatus-Wert: Google unterstützt EventRescheduled, EventCancelled, EventPostponed und EventMovedOnline — jeder Wert löst unterschiedliche Rich-Result-Darstellungen aus. Mehr dazu im Event Schema Markup vertieft Artikel.

8. Google Search Console: Monitoring und Fehlerdiagnose

Nachdem du SpecialAnnouncement implementiert hast, ist die Google Search Console dein wichtigstes Monitoring-Tool. Da SpecialAnnouncement kein dauerhafter Rich-Result-Typ ist (Google zeigt es nur bei aktiver Relevanz), gibt es spezifische Punkte zu beachten.

Validierung mit dem Rich Results Test

Prüfe dein implementiertes Schema mit dem Google Rich Results Test. Für SpecialAnnouncement gibt es eine spezifische Validierungslogik — achte auf diese Fehlermeldungen:

Fehlermeldung Ursache Lösung
"Missing required field: datePosted" datePosted fehlt oder falsch formatiert ISO 8601 Format: YYYY-MM-DDTHH:MM:SS+TZ
"Missing required field: text or url" Weder text noch url angegeben Mindestens eines von beiden ist Pflicht
"Invalid type for field: category" Kein gültiger Wikidata-URI Nur Wikidata-URIs verwenden (siehe Schema.org-Doku)
"Unknown property: diseaseSpread" Schema.org-Version veraltet Prüfe ob du https://schema.org als @context verwendest

Warum werden meine Ankündigungen nicht als Rich Result angezeigt?

SpecialAnnouncement ist ein discretionary Rich-Result-Typ — Google entscheidet selbst, ob und wann es angezeigt wird. Folgende Faktoren beeinflussen die Darstellung:

  • Relevanz zum Suchanfrage-Kontext: Die Ankündigung erscheint nur, wenn ein Nutzer tatsächlich nach der betroffenen Organisation oder dem Thema sucht.
  • Aktualität: Das expires-Datum muss in der Zukunft liegen. Abgelaufene Ankündigungen werden nicht angezeigt.
  • Seitenautorität: Behörden und bekannte Organisationen sehen öfter Rich Results als unbekannte Websites.
  • Vollständigkeit des Markups: Je mehr relevante Properties ausgefüllt sind, desto höher die Wahrscheinlichkeit für eine Rich-Result-Darstellung.
Hinweis: Wenn du keine Rich Results siehst, heißt das nicht, dass das Markup falsch ist. Google kann strukturierte Daten nutzen ohne Rich Results anzuzeigen — zum Beispiel für das Knowledge Panel oder als Qualitätssignal für den regulären Sucheintrag.

9. Implementierungs-Checkliste

Bevor du dein SpecialAnnouncement-Markup live schaltest, prüfe jeden Punkt:

  • ☑ datePosted in ISO 8601 Format mit Zeitzone (z.B. +02:00 für MESZ)
  • ☑ expires gesetzt — immer ein konkretes Datum, nie weglassen
  • ☑ text oder url vorhanden (mindestens eines, idealerweise beide)
  • ☑ category ist ein gültiger Wikidata-URI
  • ☑ author/announcementLocation hat vollständige Adressdaten
  • ☑ spatialCoverage gesetzt wenn die Ankündigung nur lokal relevant ist
  • ☑ COVID-Properties (diseaseSpread, getsVaccineAtoZ, etc.) nur bei Gesundheitsankündigungen
  • ☑ Rich Results Test: keine Fehler, nur optionale Warnungen wenn überhaupt
  • ☑ URL der Ankündigung ist die Detailseite, nicht die Startseite
  • ☑ Monitoring in Google Search Console eingerichtet
  • ☑ Ablaufprozess definiert: Wer entfernt/aktualisiert das Markup nach Ablauf?
