Technisches SEO Audit: Die vollständige Schritt-für-Schritt Anleitung 2026

Shift07 Team
11. April 2026
18 Min. Lesezeit
Tech-SEO

Ein technisches SEO-Audit ist die systematische Überprüfung aller technischen Faktoren, die beeinflussen, wie gut Google deine Website crawlt, indexiert und bewertet. Ohne eine solide technische Grundlage verpuffen selbst die besten Inhalte und Backlinks wirkungslos - denn Google kann eine Website nur gut ranken, wenn es sie auch vollständig versteht.

Dieser Pillar-Artikel führt dich Schritt für Schritt durch ein vollständiges technisches SEO-Audit: von der Crawlability-Analyse über HTTPS und Core Web Vitals bis hin zu strukturierten Daten und hreflang. Am Ende findest du eine kompakte Checkliste, die du bei jedem Audit direkt verwenden kannst.

Wann ist ein technisches SEO-Audit sinnvoll?

Führe ein Audit durch, wenn du eine neue Website launcht, nach einem Relaunch, nach einem Google-Core-Update das Traffic beeinflusst hat, vierteljährlich als Routine-Check oder wenn Rankings ohne erkennbaren Grund einbrechen.

Was gehört zu einem technischen SEO-Audit?

Ein technisches SEO-Audit umfasst acht Hauptbereiche:

  1. Crawling & Indexierung - Kann Google die Seite erreichen und indexieren?
  2. HTTPS & Sicherheit - Ist die Verbindung sicher und das Zertifikat gültig?
  3. Ladezeit & Core Web Vitals - Wie schnell lädt die Website?
  4. Mobile Optimierung - Funktioniert die Website auf Smartphones?
  5. On-Page-Elemente - Sind Meta-Tags, Canonical-Tags und Überschriften korrekt?
  6. Strukturierte Daten - Gibt es Schema-Markup für Rich Snippets?
  7. Interne Verlinkung & URL-Struktur - Ist die Navigation logisch aufgebaut?
  8. Internationale SEO - Sind hreflang-Tags korrekt (falls mehrsprachig)?

Die folgenden Schritte gehen jeden Bereich mit konkreten Prüfpunkten und Werkzeugen durch.

1

Crawling & Indexierung prüfen

Googles Crawler Googlebot muss deine Seiten zuerst finden und crawlen, bevor sie indexiert werden können. Fehler in diesem Schritt führen dazu, dass Seiten gar nicht erst in den Suchergebnissen auftauchen.

robots.txt analysieren

Die robots.txt-Datei steuert, welche Seiten Crawler besuchen dürfen. Häufige Fehler:

  • Versehentlich die gesamte Website blockiert: Disallow: / für alle User-Agents verhindert jegliches Crawling
  • Wichtige Verzeichnisse geblockt: z.B. /wp-admin/ oder /assets/ inkl. CSS/JS-Dateien die das Rendering beeinflussen
  • Sitemap nicht verlinkt: Die robots.txt sollte auf Sitemap: https://deine-domain.de/sitemap.xml verweisen

Teste deine robots.txt mit unserem kostenlosen Robots.txt-Tester.

Sitemap prüfen

Eine korrekte sitemap.xml hilft Google, alle wichtigen Seiten zu finden. Prüfe:

  • Enthält die Sitemap alle wichtigen URLs (keine gesperrten, kaputten oder duplizierten)?
  • Sind die <lastmod>-Werte korrekt und aktuell?
  • Ist die Sitemap in der Google Search Console eingereicht?
  • Größe: Eine Sitemap darf max. 50.000 URLs und 50 MB umfassen - bei größeren Websites Sitemap-Index verwenden

Validiere deine Sitemap mit dem Sitemap-Validator.

Google Search Console: Index Coverage

Die Google Search Console (GSC) ist dein wichtigstes Audit-Tool. Im Bericht "Indexabdeckung" siehst du:

  • Fehler: Seiten die nicht indexiert wurden (404, Serverseite, robots.txt geblockt)
  • Gültig mit Warnung: Indexiert, aber mit potenziellen Problemen
  • Ausgeschlossen: Bewusst nicht indexierte Seiten (noindex, canonicalized)

Praxis-Tipp: Log-Datei-Analyse

Für tief gehende Crawl-Analyse empfiehlt sich die Log-Datei-Analyse. Server-Logs zeigen dir genau, welche URLs Googlebot wann besucht hat - und welche ignoriert werden. So erkennst du Crawl-Budget-Verschwendung sofort.

2

HTTPS & Sicherheit

HTTPS ist seit 2014 ein Rankingfaktor bei Google. Ohne gültiges SSL-Zertifikat zeigen Browser Warnmeldungen an, was Benutzer abschreckt und das Vertrauen zerstört.

SSL-Zertifikat prüfen

Prüfe mit unserem SSL-Zertifikat-Checker:

  • Ist HTTPS aktiv und wird die Verbindung verschlüsselt?
  • Wann läuft das Zertifikat ab? (Erneuerung mindestens 30 Tage vorher planen)
  • Gilt das Zertifikat auch für die www-Variante der Domain?
  • Werden alle Subdomains korrekt abgedeckt (Wildcard-Zertifikat)?

Mixed Content vermeiden

Mixed Content entsteht, wenn eine HTTPS-Seite Ressourcen über HTTP lädt (z.B. Bilder, Skripte, Stylesheets). Das führt zu Browser-Warnungen und kann Rankings beeinflussen. Prüfe alle externen Ressourcen mit den Browser-Entwicklertools (F12 → Console).

Redirect von HTTP auf HTTPS

Alle HTTP-Anfragen müssen per 301-Redirect auf HTTPS umgeleitet werden. Teste, ob http://deine-domain.de und http://www.deine-domain.de korrekt auf die HTTPS-Version weiterleiten.

3

Ladezeit & Core Web Vitals

Seit dem Page Experience Update 2021 fließen die Core Web Vitals direkt in das Google-Ranking ein. Sie messen, wie schnell und stabil eine Seite aus Nutzersicht lädt.

Die drei Core Web Vitals

Metrik Was sie misst Gut Verbesserung nötig
LCP (Largest Contentful Paint) Ladezeit des größten sichtbaren Elements ≤ 2,5 Sek. > 4,0 Sek.
INP (Interaction to Next Paint) Reaktionszeit auf Nutzerinteraktionen ≤ 200 ms > 500 ms
CLS (Cumulative Layout Shift) Visuelle Stabilität (Verschiebungen) ≤ 0,1 > 0,25

Werkzeuge zur Messung

  • Google PageSpeed Insights: Analysiert Lab-Daten und Field-Daten (echte Nutzerdaten via CrUX)
  • Google Search Console → Core Web Vitals: Zeigt echte Feldaten für alle gecrawlten Seiten
  • Lighthouse (in Chrome DevTools): Lokaler Test inkl. Empfehlungen
  • Unser Core Web Vitals Erklärer für interaktive Erklärungen

Häufige Ursachen für schlechte Core Web Vitals

  • Schlechter LCP: Zu großes Hero-Bild, fehlende Bild-Optimierung, kein CDN, kein loading="eager" + fetchpriority="high" für das LCP-Element
  • Schlechter INP: Zu viel JavaScript das den Main Thread blockiert, lange Tasks, unnötige Third-Party-Scripts
  • Schlechter CLS: Bilder ohne feste Dimensionen, dynamisch eingefügte Banner, Google Fonts ohne font-display: swap
4

Mobile Optimierung

Google indexiert Websites seit 2019 ausschließlich nach dem Mobile-First-Index. Das bedeutet: Google bewertet und rankt deine Website basierend auf der mobilen Version. Wenn die mobile Version schlechter ist als die Desktop-Version, verlierst du Rankings.

Mobile Usability prüfen

  • GSC → Mobile Usability: Zeigt Fehler wie zu kleiner Text, zu eng zusammenliegende Klickziele oder Viewport nicht konfiguriert
  • Chrome DevTools → Device Mode: Simuliert verschiedene Smartphone-Bildschirme
  • Googles Mobilfreundlichkeitstest: Direkter Schnelltest einer URL

Kritische Prüfpunkte Mobile

  • Viewport-Meta-Tag vorhanden: <meta name="viewport" content="width=device-width, initial-scale=1">
  • Alle Inhalte der Desktop-Version auch auf Mobilgeräten sichtbar (keine versteckten Inhalte via CSS die Google nicht indexiert)
  • Schriftgröße mind. 16px für Fließtext
  • Klickziele mind. 48×48px groß
  • Kein horizontales Scrollen
  • Interstitials (Pop-ups die den Inhalt überdecken) vermeiden
5

On-Page-Technische Elemente

Meta-Tags überprüfen

Jede Seite braucht korrekte technische Meta-Tags. Nutze unseren Duplicate-Meta-Finder um doppelte Titles und Descriptions aufzudecken:

  • Title-Tag: Unique pro Seite, 50–60 Zeichen, Haupt-Keyword vorne
  • Meta-Description: 120–160 Zeichen, einzigartiger Call-to-Action, Haupt-Keyword enthalten
  • Meta-Robots: Kein ungewolltes noindex auf wichtigen Seiten
  • Open-Graph-Tags: og:title, og:description, og:image für Social-Media-Vorschau

Prüfe die Länge deiner Title-Tags mit dem Title-Tag-Längen-Checker.

Canonical-Tags

Der Canonical-Tag verhindert Duplicate-Content-Probleme, indem er Google mitteilt, welche URL die "echte" Seite ist. Prüfe mit dem Canonical-Tag-Checker:

  • Hat jede Seite einen Self-Canonical (<link rel="canonical" href="https://domain.de/seite/">)?
  • Verweist kein Canonical auf eine nicht-existierende URL (404)?
  • Stimmt die kanonische URL mit der in der Sitemap überein?
  • Werden URL-Varianten korrekt kanonisiert (mit/ohne www, HTTP/HTTPS, Trailing Slash)?

Heading-Struktur

Jede Seite sollte genau ein <h1>-Element haben, das das Haupt-Keyword der Seite enthält. H2- und H3-Tags strukturieren den Inhalt für Leser und Google. Prüfe mit dem Heading-Struktur-Checker.

JavaScript SEO

JavaScript-lastige Websites (Single Page Applications) stellen besondere Anforderungen. Bei JavaScript SEO gilt: Googles Renderer verarbeitet JS in einer zweiten Crawl-Phase. Das bedeutet Verzögerungen bei der Indexierung. Wichtige Inhalte sollten möglichst im HTML-Quellcode vorhanden sein (Server-Side Rendering oder Static Site Generation).

6

Strukturierte Daten (Schema Markup)

Strukturierte Daten in Form von JSON-LD helfen Google, den Inhalt deiner Seite semantisch zu verstehen. Sie können zu Rich Snippets in den Suchergebnissen führen - also zusätzlichen visuellen Elementen wie Bewertungssternen, FAQ-Akkordeons oder Produktpreisen.

Welche Schema-Typen sind relevant?

Schema-Typ Einsatzgebiet Rich-Snippet möglich
Article Blog-Artikel, News Top Stories Karussell
LocalBusiness Lokale Unternehmen Knowledge Panel, Öffnungszeiten
FAQPage Seiten mit Fragen & Antworten FAQ-Akkordeon in SERPs
Product Produktseiten Preis, Bewertungen, Verfügbarkeit
BreadcrumbList Alle Seiten mit Navigation Breadcrumbs in der URL-Anzeige

Structured Data validieren

  • Google Rich Results Test: Prüft ob deine Seite für Rich Snippets berechtigt ist
  • Schema.org Validator: Überprüft die JSON-LD-Syntax
  • GSC → Rich-Suchergebnisse: Zeigt Fehler in implementiertem Schema

Erstelle JSON-LD für lokale Unternehmen mit unserem Schema-Markup-Generator und für FAQ-Seiten mit dem FAQ-Schema-Generator.

7

URL-Struktur & Interne Verlinkung

URL-Struktur

Gute URLs sind kurz, lesbar und enthalten das Haupt-Keyword. Vermeide:

  • Zahlen-IDs statt sprechender URLs (/page?id=1234 vs. /blog/seo-tipps)
  • Zu tiefe URL-Hierarchien (maximal 3-4 Ebenen)
  • Großbuchstaben (immer Kleinschreibung verwenden)
  • Unterstriche statt Bindestriche
  • Unnötige Parameter in indexierbaren URLs

Redirect-Ketten vermeiden

Redirect-Ketten (URL A → URL B → URL C) verschlechtern Ladezeiten und verwässern Link-Stärke. Prüfe bestehende Weiterleitungen mit dem Redirect-Ketten-Tester und konsolidiere mehrfache Redirects zu einem einzigen 301.

Interne Links prüfen

  • Keine Broken Links (404-Fehler auf interne Links)
  • Jede wichtige Seite hat mindestens 3-5 interne Links von anderen Seiten
  • Ankertexte sind keyword-reich (nicht "hier klicken")
  • Keine Orphan Pages (Seiten ohne eingehende interne Links)

Analysiere deine internen Links mit dem Internal-Link-Counter.

8

Internationale SEO & Hreflang

Wenn deine Website mehrere Sprachen oder Regionen bedient, sind hreflang-Tags unverzichtbar. Sie teilen Google mit, welche URL für welche Sprache und Region gedacht ist - und verhindern, dass verschiedene Sprachversionen als Duplicate Content gewertet werden.

Hreflang-Implementierung prüfen

  • Alle Sprachversionen haben hreflang-Tags im <head>
  • Die Verlinkung ist reziprok: Wenn A auf B verweist, muss B auf A verweisen
  • Jede Sprachversion hat einen x-default-Tag (Fallback)
  • Sprachcodes sind korrekt (ISO 639-1 + ISO 3166-1 alpha-2)

Generiere korrekte hreflang-Tags mit unserem Hreflang-Tag-Generator und prüfe bestehende Tags mit dem Hreflang-Tag-Validator.

IndexNow: Neue Inhalte schnell indexieren lassen

Nachdem du alle Probleme behoben hast, solltest du Google und andere Suchmaschinen über die Änderungen informieren. IndexNow ist ein offenes Protokoll, das geänderte URLs direkt an Bing, Yandex und andere Suchmaschinen meldet. Nutze IndexNow nach:

  • Veröffentlichung neuer Seiten
  • Wichtigen Änderungen an bestehenden Seiten
  • Nach einem Relaunch

Die vollständige SEO-Audit-Checkliste

Verwende diese Checkliste bei jedem technischen SEO-Audit:

Crawling & Indexierung

robots.txt korrekt konfiguriert, keine wichtigen URLs geblockt
sitemap.xml vorhanden, valide und in GSC eingereicht
GSC Index Coverage: keine ungewollten Fehler oder Ausschlüsse
Crawl-Budget optimiert: Facettennavigation, Session-IDs per noindex/robots geblockt

HTTPS & Sicherheit

SSL-Zertifikat gültig, min. 30 Tage bis Ablauf
HTTP → HTTPS 301-Redirect aktiv
Kein Mixed Content (HTTP-Ressourcen auf HTTPS-Seiten)

Performance

LCP ≤ 2,5 Sekunden (Core Web Vitals)
INP ≤ 200 ms, CLS ≤ 0,1
Bilder komprimiert (WebP/AVIF), lazy loading für below-the-fold Bilder
Render-blocking CSS/JS minimiert oder asynchron geladen

On-Page-Technisches

Jede Seite hat eindeutigen Title (50-60 Zeichen) und Meta-Description (120-160 Zeichen)
Self-Canonical auf jeder Seite korrekt gesetzt
Genau ein H1 pro Seite mit Haupt-Keyword
Open-Graph-Tags vorhanden (og:title, og:description, og:image)

Strukturierte Daten

JSON-LD für Article, LocalBusiness oder Produkt implementiert (je nach Seitentyp)
Rich Results Test ohne Fehler bestanden

Fazit: Technisches SEO ist die Basis

Ein technisches SEO-Audit ist kein einmaliges Projekt, sondern ein kontinuierlicher Prozess. Die technische Grundlage einer Website muss stimmen, damit alle anderen SEO-Maßnahmen wirken. Nutze die obige Checkliste mindestens vierteljährlich und nach jedem größeren Website-Update.

Beginne mit den Bereichen, die den größten Hebel haben: Crawlability und Indexierung zuerst (denn ohne Indexierung gibt es keine Rankings), dann HTTPS und Core Web Vitals (da sie direkte Rankingfaktoren sind), dann die feineren On-Page-Elemente.
