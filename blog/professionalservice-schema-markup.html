ProfessionalService Schema Markup: Unternehmensberater, Architekten und Dienstleister für Google

25. April 2026 · Schema Markup · 13 Min. Lesezeit

Während Restaurants, Ärzte und Hotels bereits zahlreiche spezialisierte Schema.org-Typen besitzen, stehen viele Dienstleistungsunternehmen vor einer Herausforderung: Für Unternehmensberater, Architekten, PR-Agenturen oder IT-Dienstleister gibt es keinen dediziert maßgeschneiderten Typ. Hier kommt ProfessionalService ins Spiel — der universelle Schema.org-Typ für strukturierte Daten aller Dienstleistungsanbieter, die nicht in eine der engeren Kategorien passen.

In diesem Artikel erfährst du, wie du ProfessionalService korrekt implementierst, welche Properties den größten SEO-Mehrwert bringen und wie du spezialisierte Varianten für verschiedene Branchen aufbaust. Außerdem zeigen wir dir, wann du ProfessionalService verwenden solltest und wann ein spezifischerer Typ die bessere Wahl ist.

Was ist ProfessionalService in Schema.org?

ProfessionalService ist in der Schema.org-Hierarchie ein direkter Sub-Typ von LocalBusiness. Es handelt sich um einen breiten Sammeltyp für qualifizierte Dienstleistungsberufe, für die kein spezifischerer Schema.org-Typ existiert. Typische Anwendungsfälle:

  • Unternehmensberatungen, Management-Consulting, Strategieberatung
  • Architekturbüros, Innenarchitekten, Stadtplaner
  • PR-Agenturen, Werbeagenturen, Marketing-Beratungen
  • IT-Dienstleister, Webagenturen, Software-Entwicklungsfirmen
  • Steuerberatungen (wenn kein AccountingService bevorzugt wird)
  • Ingenieur- und Planungsbüros
  • Personalberatungen, Headhunter, HR-Agenturen
  • Coaches, Business Coaches, Karriereberater
  • Versicherungsmakler, Finanzberater

Der wichtigste Grundsatz: Verwende ProfessionalService wenn kein präziserer Typ verfügbar ist. Für Zahnärzte gibt es Dentist, für Restaurants Restaurant, für Anwälte gibt es LegalService. Aber für eine Unternehmensberatung ist ProfessionalService die korrekte Wahl.

Minimales ProfessionalService-Schema: Das Pflicht-Set

Beginnen wir mit den absoluten Pflichtfeldern — das sind die Properties, die Google für eine korrekte Einordnung benötigt:

{
  "@context": "https://schema.org",
  "@type": "ProfessionalService",
  "name": "Thümmler Consulting GmbH",
  "url": "https://thuemmler-consulting.de",
  "telephone": "+49 30 123456",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "Unter den Linden 1",
    "addressLocality": "Berlin",
    "postalCode": "10117",
    "addressCountry": "DE"
  }
}

Dieses Minimum reicht für die korrekte Indexierung — für Rich Results und eine starke Darstellung im Knowledge Panel brauchst du deutlich mehr. Im Folgenden gehen wir alle wichtigen Properties durch.

Tipp zu areaServed: Für Beratungsunternehmen, die bundesweit oder international tätig sind, ist areaServed besonders wichtig. Du kannst nicht nur Country- sondern auch State-Objekte (für einzelne Bundesländer) oder City-Objekte angeben. Je spezifischer du das Einzugsgebiet definierst, desto besser kann Google dich lokalen Suchanfragen zuordnen.

ProfessionalService für verschiedene Branchen: Spezialisierte Beispiele

Architekturbüro

Architekturbüros haben eine besondere Eigenschaft: Sie können Arbeitsergebnisse (Projekte, Bauwerke) als Product oder über workPerformed einbinden. Außerdem ist der Nachweis von Qualifikationen und Mitgliedschaften für E-E-A-T relevant:

Die wichtigsten Properties im Überblick

Property Typ SEO-Mehrwert Wichtigkeit
name Text Grundidentifikation Pflicht
description Text Knowledge Panel, Snippets Hoch
areaServed AdministrativeArea / Text Lokale Suchen, Geo-Targeting Hoch
hasOfferCatalog OfferCatalog Leistungsübersicht in Google Hoch
knowsAbout Text / Thing E-E-A-T, Expertise-Signale Mittel
hasCredential EducationalOccupationalCredential Trustworthiness, E-E-A-T Mittel

foundingDate Date Vertrauenssignal Unternehmensalter Niedrig

knowsAbout und hasCredential: E-E-A-T stärken

Das Google-Konzept E-E-A-T (Experience, Expertise, Authoritativeness, Trustworthiness) ist für Dienstleister besonders kritisch. Potenzielle Kunden suchen nicht nur nach einem Service, sondern nach einem vertrauenswürdigen Experten. Hier helfen zwei oft unterschätzte Properties:

knowsAbout

knowsAbout akzeptiert sowohl freie Texte als auch verlinkbare Thing-Entitäten. Die Verwendung als Textarray ist am einfachsten und trotzdem wirksam:

"knowsAbout": [
  "Agiles Projektmanagement",
  "Scrum und Kanban",
  "ISO 27001 Informationssicherheit",
  "Datenschutz nach DSGVO"
]

hasCredential

Zertifizierungen und Berufszulassungen als EducationalOccupationalCredential einzubinden stärkt das Vertrauenssignal erheblich. Besonders relevant für: Steuerberater (Kammerzulassung), Architekten (Kammereintragung), Wirtschaftsprüfer und ähnliche reglementierte Berufe.

"hasCredential": [
  {
    "@type": "EducationalOccupationalCredential",
    "name": "Steuerberater-Zulassung",
    "credentialCategory": "Berufliche Zulassung",
    "recognizedBy": {
      "@type": "Organization",
      "name": "Bundessteuerberaterkammer"
    }
  }
]
Wichtig für Steuerberater: Es gibt in Schema.org auch den spezialisierteren Typ AccountingService (Sub-Typ von ProfessionalService). Wenn du eine Steuerberatungskanzlei betreibst, bevorzuge AccountingService gegenüber dem generischen ProfessionalService. Der spezifischere Typ gibt Google ein präziseres Signal.

areaServed: Geografisches Targeting für Dienstleister

Dienstleister sind oft nicht an einen physischen Standort gebunden — eine Unternehmensberatung aus München berät Kunden bundesweit. Das Property areaServed kommuniziert dieses Einzugsgebiet explizit an Google:

// National tätig
"areaServed": {
  "@type": "Country",
  "name": "Deutschland"
}

// Regional tätig (Bundesland)
"areaServed": [
  {
    "@type": "State",
    "name": "Bayern"
  },
  {
    "@type": "State",
    "name": "Baden-Württemberg"
  }
]

// Lokal tätig (mehrere Städte)
"areaServed": [
  {
    "@type": "City",
    "name": "München"
  },
  {
    "@type": "City",
    "name": "Augsburg"
  },
  {
    "@type": "City",
    "name": "Ingolstadt"
  }
]

Wer nur lokal tätig ist, kann areaServed auch mit dem ServiceArea-Schema kombinieren und ein geografisches Einzugsgebiet mit Umkreis angeben.

ProfessionalService mit Person-Schema kombinieren

Für kleine Beratungsbüros, Freiberufler und Ein-Mann-Agenturen ist die Kombination von ProfessionalService mit einem Person-Schema besonders effektiv. Google kann dann sowohl das Unternehmen als auch die Gründerin oder den Gründer als separate Entitäten verstehen:

[
  {
    "@context": "https://schema.org",
    "@type": "ProfessionalService",
    "name": "Meier Digital Consulting",
    "url": "https://meier-digital.de",
    "founder": {
      "@type": "Person",
      "name": "Claudia Meier",
      "jobTitle": "Gründerin und Geschäftsführerin",
      "url": "https://meier-digital.de/ueber-mich",
      "sameAs": "https://www.linkedin.com/in/claudiameier"
    },
    "employee": {
      "@type": "Person",
      "name": "Claudia Meier",
      "jobTitle": "Unternehmensberaterin"
    }
  },
  {
    "@context": "https://schema.org",
    "@type": "Person",
    "name": "Claudia Meier",
    "jobTitle": "Unternehmensberaterin und Digitalisierungsexpertin",
    "url": "https://meier-digital.de/ueber-mich",
    "worksFor": {
      "@type": "Organization",
      "name": "Meier Digital Consulting"
    },
    "knowsAbout": [
      "Digitalisierung im Mittelstand",
      "Agile Transformation",
      "ERP-Implementierung"
    ]
  }
]

Häufige Fehler bei ProfessionalService-Schemas

  1. Falschen Typ verwenden: Für Ärzte nicht ProfessionalService nehmen — es gibt Physician und MedicalClinic. Immer den spezifischsten verfügbaren Typ wählen.
  2. description zu kurz: Die Beschreibung sollte 50–200 Zeichen haben. Zu kurze Descriptions (unter 30 Zeichen) werden von Google ignoriert.
  3. areaServed vergessen: Dienstleister ohne areaServed werden nur in der unmittelbaren Nähe des Standorts für lokale Suchen ausgespielt.
  4. hasOfferCatalog ohne Inhalte: Ein leerer OfferCatalog ist schlechter als kein OfferCatalog — lass das Property weg wenn du keine Leistungen eintragen willst.
  5. sameAs-URLs nicht pflegen: Veraltete LinkedIn-URLs oder gelöschte Social-Profile als sameAs schaden dem Trust-Score.

Checkliste: ProfessionalService Schema vollständig

  • ✅ Richtiger Typ: Gibt es einen spezifischeren Sub-Typ als ProfessionalService?
  • ✅ name, url, telephone, address ausgefüllt?
  • ✅ description — 50–200 Zeichen, keyword-reich?
  • ✅ areaServed — lokale, regionale oder nationale Tätigkeitsregion?
  • ✅ hasOfferCatalog mit den wichtigsten Dienstleistungen?
  • ✅ knowsAbout und/oder hasCredential für E-E-A-T?
  • ✅ aggregateRating wenn Kundenbewertungen vorhanden?
  • ✅ sameAs mit aktuellen Social-Media-Profilen?
  • ✅ Im JSON-LD Validator geprüft?
  • ✅ Canonical Tag gesetzt?

Fazit: ProfessionalService als SEO-Hebel für Dienstleister

Für alle Dienstleistungsunternehmen, die nicht unter einen spezifischen Schema.org-Typ fallen, ist ProfessionalService das mächtigste Werkzeug im strukturierten Daten-Arsenal. Die Kombination aus vollständiger Adresse, areaServed für das Einzugsgebiet, hasOfferCatalog für die Leistungen und knowsAbout bzw. hasCredential für E-E-A-T ergibt ein Schema, das Google nicht nur versteht, sondern auch in der Suche honoriert.

Der nächste Schritt: Validiere dein fertiges Schema mit dem Google Rich Results Test und überprüfe, ob ein Knowledge-Panel-Eintrag für dein Unternehmen erscheint.
