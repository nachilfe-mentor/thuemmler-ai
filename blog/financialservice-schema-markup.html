FinancialService Schema Markup: Finanzberater und Versicherungsmakler für Google optimieren

FinancialService Schema Markup richtig implementieren — mit vollständigen JSON-LD-Beispielen für Finanzberater, Versicherungsmakler, Bankberater und Vermögensverwalter.

Finanzdienstleister haben eine besondere SEO-Herausforderung: Ihre Branche ist von Google als YMYL (Your Money or Your Life) eingestuft — also als Bereich, in dem fehlerhafte Informationen erhebliche finanzielle Schäden anrichten können. Google bewertet Websites in diesem Bereich besonders streng. Strukturierte Daten mit FinancialService Schema Markup helfen Google dabei, dein Unternehmen korrekt einzuordnen und deine Glaubwürdigkeit zu signalisieren.

In diesem Artikel lernst du, welches Schema für deinen Unternehmenstyp passt, wie du es korrekt implementierst und welche Fehler du unbedingt vermeiden solltest.

Was ist FinancialService in schema.org?

FinancialService ist ein Typ aus dem LocalBusiness-Schema, der Finanzdienstleistungsunternehmen beschreibt. Er ist in der schema.org-Hierarchie ein Subtyp von LocalBusiness, der wiederum ein Subtyp von Organization ist.

Die wichtigste Eigenschaft von FinancialService: Er ist bewusst allgemein gehalten und bildet den Ausgangspunkt für eine ganze Familie spezialisierter Sub-Typen:

Schema-Typ Geeignet für Beispiele
FinancialService Allgemeine Finanzdienstleister Vermögensberater, Finanzplaner, Bankberater
AccountingService Steuerberater, Buchhalter Steuerberatungskanzleien, Lohnbuchhaltung
InsuranceAgency Versicherungsvermittler Versicherungsmakler, Versicherungsagenturen
BankOrCreditUnion Banken, Kreditinstitute Sparkassen, Volksbanken, Privatbanken
ExchangeRatesProvider Devisenhandel, Wechselstuben Forex-Broker, Wechselstuben

Empfehlung: Immer den spezifischsten Typ verwenden

Steuerberater sollten AccountingService verwenden, Versicherungsmakler InsuranceAgency. Je spezifischer der Typ, desto besser kann Google dein Unternehmen einordnen.

BankOrCreditUnion: Besonderheiten für Banken und Sparkassen

Banken, Sparkassen und Kreditgenossenschaften verwenden den Typ BankOrCreditUnion. Dieser Typ hat keine spezifischen zusätzlichen Properties gegenüber FinancialService, ist aber semantisch präziser:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BankOrCreditUnion",
  "name": "Volksbank Musterstadt eG — Filiale Marktplatz",
  "url": "https://www.volksbank-musterstadt.de/filiale-marktplatz",
  "telephone": "+49 1234 56789-0",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "Marktplatz 1",
    "postalCode": "12345",
    "addressLocality": "Musterstadt",
    "addressCountry": "DE"
  },
  "openingHours": [
    "Mo 09:00-16:00",
    "Di 09:00-16:00",
    "Mi 09:00-13:00",
    "Do 09:00-18:00",
    "Fr 09:00-16:00"
  ],
  "branchOf": {
    "@type": "BankOrCreditUnion",
    "name": "Volksbank Musterstadt eG",
    "url": "https://www.volksbank-musterstadt.de"
  }
}
</script>

Beachte die Property branchOf: Sie verlinkt eine Filiale auf das Hauptunternehmen. Das ist besonders bei Banken mit mehreren Filialen wichtig und stärkt das semantische Netz zwischen den Seiten.

Warum FinancialService Schema für YMYL-Websites so wichtig ist

Google hat für YMYL-Websites (Gesundheit, Recht, Finanzen) besonders hohe E-E-A-T-Anforderungen: Experience, Expertise, Authoritativeness, Trustworthiness. Schema Markup unterstützt diese Signale auf drei Wegen:

  • Authoritativeness: Korrekte Geschäftsdaten (Name, Adresse, Telefon) zeigen, dass du ein echtes, legitimes Unternehmen bist.
  • Trustworthiness: Bewertungen (aggregateRating) und konsistente sameAs-Verlinkungen (LinkedIn, Google My Business) stärken das Vertrauen.
  • Expertise: Das hasOfferCatalog mit spezifischen Dienstleistungen zeigt, auf welche Bereiche du spezialisiert bist.

Wichtig für YMYL-Seiten

Stelle sicher, dass alle Daten im Schema exakt mit deiner Website übereinstimmen. Widersprüche zwischen Schema-Daten und dem sichtbaren Inhalt (z.B. andere Öffnungszeiten) können sich negativ auf dein Trust-Signal auswirken.

Häufige Fehler bei FinancialService Schema

1. Falschen Typ verwenden

Steuerberater verwenden manchmal ProfessionalService statt AccountingService, oder Versicherungsmakler nehmen FinancialService statt InsuranceAgency. Immer den spezifischsten zutreffenden Typ wählen.

2. Unvollständige Adresse

Die addressCountry-Property ("DE") wird oft vergessen. Ohne sie kann Google die Adresse nicht eindeutig einem Land zuordnen — was die lokale Suchsichtbarkeit verringert.

3. Öffnungszeiten im falschen Format

Google erwartet das Format "Mo-Fr 09:00-18:00" oder für einzelne Tage "Mo 09:00-17:00". Varianten wie "Montag bis Freitag" oder "9-18 Uhr" werden nicht erkannt.

4. Bewertungen ohne Rezensionen auf der Seite

Wenn du aggregateRating angibst, aber keine tatsächlichen Bewertungen auf der Seite angezeigt werden, kann Google das als irreführend werten und die Rich Snippets nicht anzeigen. Die Bewertungsdaten müssen auf der Seite sichtbar sein.

5. Mehrfach-Schema ohne Qualifizierung

Wenn du mehrere Filialen auf einer Seite darstellen möchtest, verwende ein Array von Schema-Objekten oder separate Schema-Blöcke mit @graph. Vermeide es, mehrere separate <script type="application/ld+json">-Blöcke mit demselben Typ auf einer Seite zu haben.

Schema Markup mit @graph für mehrere Entitäten

Wenn du auf einer Seite gleichzeitig das Unternehmen und die Website beschreiben möchtest (z.B. für WebSite-Schema), nutze @graph:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "FinancialService",
      "@id": "https://www.schmidt-finanzberatung.de/#organization",
      "name": "Schmidt Finanzberatung GmbH",
      "url": "https://www.schmidt-finanzberatung.de",
      "address": {
        "@type": "PostalAddress",
        "streetAddress": "Mönckebergstraße 12",
        "postalCode": "20095",
        "addressLocality": "Hamburg",
        "addressCountry": "DE"
      }
    },
    {
      "@type": "WebSite",
      "@id": "https://www.schmidt-finanzberatung.de/#website",
      "url": "https://www.schmidt-finanzberatung.de",
      "name": "Schmidt Finanzberatung",
      "publisher": {
        "@id": "https://www.schmidt-finanzberatung.de/#organization"
      }
    }
  ]
}
</script>

Durch die @id-Referenzierung entstehen semantische Verbindungen zwischen den Entitäten — ein starkes Signal für Google's Knowledge Graph.

Schritt-für-Schritt: FinancialService Schema einbauen

  1. Typ bestimmen: Bin ich AccountingService, InsuranceAgency, BankOrCreditUnion oder allgemein FinancialService?
  2. JSON-LD erstellen: Nutze unseren AccountingService & FinancialService Schema Generator für ein vollständiges Markup in Minuten.
  3. In den <head> einbauen: Den generierten Code direkt vor dem schließenden </head>-Tag einfügen.
  4. Validieren: Mit dem Google Rich Results Test prüfen, ob Fehler vorliegen.
  5. In der Search Console überwachen: Unter "Verbesserungen" erscheinen nach einigen Tagen Hinweise auf erkannte strukturierte Daten.

Welche Rich Results sind für FinancialService möglich?

Google zeigt für FinancialService keine eigene Rich-Results-Kategorie an, aber folgende Elemente können sichtbar werden:

  • Bewertungssterne im organischen Suchergebnis (wenn aggregateRating korrekt eingebunden ist)
  • Lokales Knowledge Panel mit Adresse, Öffnungszeiten und Telefonnummer
  • Breadcrumbs in der URL-Darstellung (bei BreadcrumbList-Schema)
  • Sitelinks (werden automatisch von Google generiert, Schema kann sie unterstützen)

Der größte praktische Nutzen ist das lokale Knowledge Panel, das bei gezielten Suchen nach dem Unternehmen erscheint. Korrekte strukturierte Daten erhöhen die Wahrscheinlichkeit, dass dieses Panel vollständig und korrekt befüllt wird.

Fazit: FinancialService Schema lohnt sich besonders für YMYL

Gerade in einer YMYL-Branche wie Finanzdienstleistungen ist Schema Markup mehr als ein technisches Detail — es ist ein direktes Signal an Google, dass dein Unternehmen legitim, vertrauenswürdig und lokal präsent ist. Die Implementierung dauert weniger als 30 Minuten und kann langfristig die Sichtbarkeit in der lokalen Suche spürbar verbessern.
