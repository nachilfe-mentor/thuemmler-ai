FAQ Schema Markup vertieft: FAQPage JSON-LD vollständig implementieren 2026

Schema Markup

FAQ Schema Markup ist eine der wenigen Schema-Implementierungen, die garantiert sichtbare Auswirkungen in den Google-Suchergebnissen erzeugen können - durch direkt unterhalb des Suchergebnisses angezeigte Frage-Antwort-Paare. Unser Einführungsartikel zu FAQPage Schema hat die Grundlagen erklärt. In diesem Artikel gehen wir tiefer: Wir behandeln fortgeschrittene Implementierungsstrategien, selten diskutierte Validierungsregeln, Kombinationsstrategien mit anderen Schema-Typen und systematische Fehlerquellen, die viele Entwickler übersehen.

FAQPage: Die offizielle Definition und ihre Implikationen

Schema.org definiert FAQPage als Untertyp von WebPage - und das hat weitreichende Konsequenzen. Eine FAQPage ist nicht einfach eine Seite mit einigen Fragen und Antworten. Es ist eine Seite, die ausschließlich oder primär aus Frage-Antwort-Paaren besteht, bei denen jede Frage genau eine Antwort hat.

Das unterscheidet FAQPage von anderen ähnlichen Typen:

  • FAQPage - Statische FAQ, eine Antwort pro Frage, vom Websitebetreiber verfasst
  • QAPage - Community-Fragen mit mehreren möglichen Antworten, verschiedene Autoren (wie Stack Overflow)
  • HowToStep - Anleitungsschritte, keine Frage-Antwort-Struktur

Wenn du FAQPage für Community-Inhalte verwendest, bei denen Nutzer Antworten abstimmen können, verletzt das die Google-Richtlinien. Nutze für solche Fälle QAPage.

Die vollständige FAQPage-Struktur im Detail

Hier ist die vollständige, valide FAQPage-Implementierung mit allen unterstützten Properties:

{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Was ist FAQ Schema Markup?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "<p>FAQ Schema Markup ist ein strukturiertes Datenformat nach Schema.org-Standard. Es teilt Google mit, dass eine Seite Frage-Antwort-Paare enthält. Google kann diese Paare direkt in den Suchergebnissen als Rich Snippets anzeigen - als aufklappbare Akkordeon-Liste unterhalb des normalen Suchergebnisses.</p>"
      }
    },
    {
      "@type": "Question",
      "name": "Wie viele Fragen sollte eine FAQ-Seite enthalten?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "<p>Es gibt kein offizielles Minimum oder Maximum. Jedoch zeigt Google in den Rich Results typischerweise <strong>2-3 Fragen</strong> direkt an. Mehr Fragen bedeuten mehr potenzielle Anzeigemöglichkeiten. Empfehlenswert sind 5-10 wirklich relevante Fragen statt 20 dünn befüllter.</p>"
      }
    }
  ]
}

HTML in Antworten: Was erlaubt ist

Eine wenig bekannte, aber sehr nützliche Eigenschaft von FAQPage: Du kannst im text-Feld der Antwort eingeschränktes HTML verwenden. Google unterstützt folgende Tags:

  • <p> - Absätze (sehr empfohlen für Lesbarkeit)
  • <strong>, <b> - Fettschrift
  • <em>, <i> - Kursivschrift
  • <ul>, <ol>, <li> - Listen
  • <a href="..."> - Links (intern und extern)
  • <br> - Zeilenumbruch

Nicht erlaubt sind: <h1>-<h6>, <div>, <span>, Bilder, iframes, JavaScript oder CSS. HTML-Sonderzeichen müssen kodiert werden: &lt; statt <, &gt; statt >, &amp; statt &.

Kombination mit WebPage und Article

Da FAQPage ein Untertyp von WebPage ist, kannst du beide Konzepte kombinieren. Auf Seiten, die sowohl Artikel-Inhalt als auch eine FAQ-Sektion haben, empfiehlt sich folgende Struktur:

[
  {
    "@context": "https://schema.org",
    "@type": "Article",
    "headline": "Mein Fachartikel",
    "mainEntityOfPage": {
      "@id": "https://deine-website.de/mein-artikel/#webpage"
    },
    "author": { "@type": "Person", "name": "Max Mustermann" },
    "datePublished": "2026-04-18"
  },
  {
    "@context": "https://schema.org",
    "@type": "FAQPage",
    "@id": "https://deine-website.de/mein-artikel/#faqpage",
    "mainEntity": [
      {
        "@type": "Question",
        "name": "Häufig gestellte Frage zum Artikel-Thema?",
        "acceptedAnswer": {
          "@type": "Answer",
          "text": "<p>Die Antwort auf die Frage in 2-3 Sätzen.</p>"
        }
      }
    ]
  }
]

Diese Kombination signalisiert Google: Es gibt einen informativen Artikel (Article) mit ergänzenden FAQ-Snippets (FAQPage). Das kann zu zwei verschiedenen Rich-Snippet-Darstellungen führen - der reguläre Ergebniseintrag und zusätzlich die aufklappbaren Fragen.

FAQPage und HowTo: Die ideale Kombination für Anleitungsseiten

Anleitungsseiten profitieren oft von beiden Markup-Typen gleichzeitig. Der Hauptinhalt ist ein HowTo (Schritt-für-Schritt-Anleitung), während häufige Fragen zur Anleitung in einem FAQPage-Block am Ende beantwortet werden:

[
  {
    "@context": "https://schema.org",
    "@type": "HowTo",
    "name": "Wie installiere ich ein SSL-Zertifikat?",
    "step": [
      { "@type": "HowToStep", "position": 1, "text": "..." },
      { "@type": "HowToStep", "position": 2, "text": "..." }
    ]
  },
  {
    "@context": "https://schema.org",
    "@type": "FAQPage",
    "mainEntity": [
      {
        "@type": "Question",
        "name": "Was kostet ein SSL-Zertifikat?",
        "acceptedAnswer": {
          "@type": "Answer",
          "text": "<p>Let's Encrypt bietet kostenlose SSL-Zertifikate. Kommerzielle Zertifikate kosten zwischen 10 und 300 Euro pro Jahr.</p>"
        }
      }
    ]
  }
]

Validierungsregeln, die oft übersehen werden

Regel 1: Fragen müssen auf der Seite sichtbar sein

Google erfordert, dass die im Schema ausgewiesenen Fragen und Antworten tatsächlich auf der Seite sichtbar sind - nicht nur im Schema-Markup. Wenn ein Nutzer die Seite öffnet, muss er die Fragen und Antworten lesen können (auch wenn sie in einem Akkordeon versteckt sind, aber aufgeklappt werden können).

Verboten: Fragen im Schema, die nicht im HTML-Content der Seite erscheinen.

Regel 2: Keine Werbebotschaften in Antworten

Google lässt FAQ Rich Results nicht erscheinen, wenn die Antworten hauptsächlich Werbebotschaften, Preisangaben oder Call-to-Action-Texte ohne inhaltlichen Mehrwert enthalten. Die Antwort muss eine echte Frage beantworten - nicht ein Produkt verkaufen.

Verboten: "Kaufen Sie jetzt unser Premium-Paket für nur 49 Euro!"

Erlaubt: "Die Preise variieren je nach Anbieter. Typischerweise kosten solche Dienstleistungen zwischen 50 und 200 Euro monatlich."

Regel 3: Maximale Antwortlänge beachten

Für Rich Results empfiehlt Google Antworten von maximal 300 Zeichen in der primären Darstellung. Längere Antworten werden in den Suchergebnissen abgeschnitten. Im Markup kann die Antwort länger sein - aber die ersten 300 Zeichen sollten die wichtigste Information enthalten.

Regel 4: Identische Fragen auf mehreren Seiten

Ein häufiger Fehler ist, dieselben FAQ-Fragen auf mehreren Seiten der Website zu verwenden. Google kann dann nicht unterscheiden, welche Seite die maßgebliche Antwort enthält, und zeigt möglicherweise keine der Seiten als Rich Result an.

Lösung: Jede FAQ-Seite sollte einzigartige, seitenspezifische Fragen enthalten. Globale FAQ-Seiten (z.B. "Wie lange dauert die Lieferung?") gehören auf eine zentrale FAQ-Seite und sollten nicht auf Produktseiten dupliziert werden.

Erweiterte Fragetypen: Fragen mit Links und strukturierten Antworten

Da Antworten HTML-Links enthalten dürfen, kannst du FAQs strategisch für interne Verlinkung nutzen:

{
  "@type": "Question",
  "name": "Wie kann ich meine Website für Google optimieren?",
  "acceptedAnswer": {
    "@type": "Answer",
    "text": "<p>SEO umfasst drei Hauptbereiche: <strong>Technisches SEO</strong> (Ladezeit, HTTPS, Strukturierte Daten), <strong>On-Page SEO</strong> (Keywords, Content, Überschriften) und <strong>Off-Page SEO</strong> (Backlinks, Social Signals).</p><p>Beginne mit einer kostenlosen <a href='https://shift07.ai'>SEO-Analyse deiner Website</a>, um konkrete Verbesserungsmöglichkeiten zu identifizieren.</p>"
  }
}

Die enthaltenen Links werden von Google verfolgt und können den Linkjuice zu den verlinkten Seiten leiten - ein oft übersehener SEO-Vorteil von FAQ Schema.

FAQ Schema für lokale Unternehmen

Lokale Unternehmen können FAQPage besonders effektiv einsetzen. Kombiniert mit LocalBusiness Schema ergibt sich eine mächtige Kombination:

[
  {
    "@context": "https://schema.org",
    "@type": "LocalBusiness",
    "name": "Zahnarztpraxis Dr. Müller",
    "address": {
      "@type": "PostalAddress",
      "streetAddress": "Musterstraße 42",
      "addressLocality": "München",
      "postalCode": "80331",
      "addressCountry": "DE"
    },
    "openingHours": "Mo-Fr 08:00-18:00"
  },
  {
    "@context": "https://schema.org",
    "@type": "FAQPage",
    "mainEntity": [
      {
        "@type": "Question",
        "name": "Nehmen Sie auch Kassenpatienten an?",
        "acceptedAnswer": {
          "@type": "Answer",
          "text": "<p>Ja, wir behandeln sowohl Kassen- als auch Privatpatienten. Bitte vereinbaren Sie telefonisch einen Termin unter +49 89 12345678.</p>"
        }
      },
      {
        "@type": "Question",
        "name": "Wie lange ist die Wartezeit auf einen Termin?",
        "acceptedAnswer": {
          "@type": "Answer",
          "text": "<p>Aktuell beträgt die Wartezeit auf einen regulären Termin etwa 2-3 Wochen. In dringenden Fällen versuchen wir, Sie innerhalb von 48 Stunden zu behandeln.</p>"
        }
      }
    ]
  }
]

Strategie: Welche Fragen eignen sich für FAQ Schema?

Nicht jede Frage ist gleich gut für FAQ Rich Results. Die besten Kandidaten haben folgende Eigenschaften:

Hoch geeignet

  • Fragen, nach denen Nutzer tatsächlich bei Google suchen (recherchiere mit Google Suggest)
  • Fragen, die direkt zum Thema der Seite passen
  • Fragen mit kurzen, präzisen Antworten (100-200 Zeichen)
  • Fragen, die Conversion-relevante Bedenken adressieren ("Wie läuft die Kündigung ab?")

Weniger geeignet

  • Sehr allgemeine Fragen, die auf anderen Seiten bereits beantwortet werden
  • Fragen mit sehr langen, komplexen Antworten
  • Fragen, die mehrere mögliche Antworten haben (eher für QAPage)
  • Führungsfragen, die offensichtlich als Werbung formuliert sind

Diagnose: Warum Google die FAQ Rich Results nicht anzeigt

FAQ Rich Results erscheinen nicht automatisch - auch bei korrektem Markup. Hier sind die häufigsten Gründe, warum Google sie unterdrückt:

  • Seite rankt nicht gut genug: Google zeigt Rich Results bevorzugt für Seiten, die in der Top 10 ranken. Neue oder schlecht rankende Seiten erhalten seltener Rich Results.
  • Fragen nicht im HTML sichtbar: Wenn die Fragen nur im JSON-LD stehen, nicht aber im sichtbaren HTML-Content.
  • Zu wenig E-E-A-T: Bei YMYL-Themen (Gesundheit, Finanzen) sind die Anforderungen höher.
  • Richtlinienverstöße: Werbebotschaften, irreführende Antworten oder manipulative Frageformulierungen.
  • Zu viele Seiten mit identischen FAQ: Duplicate-FAQ-Problem (s. o.).

Validiere dein Markup mit dem JSON-LD Structured Data Validator und dem Google Rich Results Test. Der Google-Test zeigt auch, ob Rich Results für deine Seite in Frage kommen - oder warum nicht.

FAQ Schema und Featured Snippets: Der Unterschied

Ein wichtiges Missverständnis: FAQ Rich Results und Featured Snippets sind zwei völlig unterschiedliche SERP-Features. Featured Snippets erscheinen über den regulären Ergebnissen (Position 0) und basieren auf inhaltlicher Relevanz, nicht auf Schema Markup. FAQ Rich Results erscheinen unter deinem regulären Ergebnis und basieren auf dem FAQPage-Schema.

Theoretisch kann eine Seite beides gleichzeitig erhalten - Featured Snippet für eine Hauptfrage und FAQ Rich Results für ergänzende Fragen. Das maximiert die SERP-Fläche erheblich.

Checkliste: FAQPage Schema vollständig und korrekt

  • ☐ @type: "FAQPage" korrekt gesetzt
  • ☐ mainEntity ist ein Array von Question-Objekten
  • ☐ Jede Question hat name (die Frage als vollständigen Satz)
  • ☐ Jede Question hat acceptedAnswer mit @type: "Answer"
  • ☐ Jede Answer hat text mit der Antwort
  • ☐ HTML in Antworten korrekt kodiert (&lt; statt <)
  • ☐ Fragen sind im sichtbaren HTML der Seite vorhanden
  • ☐ Keine Werbebotschaften in Antworten
  • ☐ Keine identischen Fragen auf anderen Seiten der Domain
  • ☐ Antworten beginnen mit dem wichtigsten Inhalt (max. 300 Zeichen in der Vorschau)
  • ☐ Mit JSON-LD Validator und Google Rich Results Test geprüft

Fazit: FAQPage Schema strategisch einsetzen

FAQPage Schema ist eines der wenigen Markup-Typen, die direkt messbare SERP-Sichtbarkeit erzeugen können. Richtig eingesetzt - mit echten, suchanfragenrelevanten Fragen, korrektem HTML-Encoding und strategischer Kombination mit anderen Schema-Typen - kann es die Klickrate erheblich steigern.

Die häufigsten Fehler (Werbebotschaften in Antworten, Fragen nicht im HTML, Duplicate-FAQ) lassen sich leicht vermeiden, wenn du die Google-Richtlinien konsequent befolgst.
