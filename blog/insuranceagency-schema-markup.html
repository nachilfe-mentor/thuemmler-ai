InsuranceAgency Schema Markup: Versicherungsmakler und Versicherungsagenturen für Google optimieren

So implementierst du InsuranceAgency Schema Markup korrekt — mit vollständigem JSON-LD-Beispiel, allen relevanten Properties und einer Schritt-für-Schritt-Anleitung für Versicherungsvermittler.

Versicherungsmakler und Versicherungsagenturen arbeiten in einer Branche, die Google als YMYL (Your Money or Your Life) einstuft. Das bedeutet: Google bewertet Websites in diesem Bereich besonders kritisch und legt besonderen Wert auf Vertrauen, Expertise und korrekte Unternehmensdaten. Genau hier setzt InsuranceAgency Schema Markup an.

Mit richtig implementiertem JSON-LD-Schema signalisierst du Google, dass dein Unternehmen legitim ist, lokal präsent ist und klar definierte Dienstleistungen anbietet. Das Ergebnis: bessere lokale Sichtbarkeit, ein vollständigeres Knowledge Panel und langfristig stärkere E-E-A-T-Signale.

InsuranceAgency in der schema.org-Hierarchie

InsuranceAgency ist in der schema.org-Hierarchie wie folgt eingeordnet:

Thing
  └── Organization
        └── LocalBusiness
              └── FinancialService
                    └── InsuranceAgency

Als Subtyp von FinancialService (mehr dazu im Artikel FinancialService Schema Markup) erbt InsuranceAgency alle Properties seines Elterntyps. Du kannst also sämtliche LocalBusiness-Properties verwenden — Adresse, Öffnungszeiten, Telefon, Bewertungen — und sie auf einen Versicherungsbetrieb anwenden.

Makler vs. Agent: Welcher Typ ist richtig?

schema.org unterscheidet nicht explizit zwischen Versicherungsmakler (unabhängig) und Versicherungsagent (an einen Versicherer gebunden). Beide verwenden InsuranceAgency. Die Unterscheidung kannst du in der description-Property oder über hasOfferCatalog mit den angebotenen Produkten kommunizieren.

Property-Referenz für InsuranceAgency

Property Pflicht? Wichtigkeit Hinweis
name ✅ Pflicht Hoch Offizieller Firmenname, wie im Impressum
url ✅ Pflicht Hoch Kanonische URL der Seite, auf der das Schema sitzt
address ✅ Für lokale Suche Sehr hoch Vollständig mit PLZ, Ort, addressCountry: "DE"
telephone Empfohlen Hoch Format: +49 221 ... (internationale Schreibweise)
openingHours Empfohlen Hoch Format: "Mo-Fr 09:00-18:00" — erscheint im Knowledge Panel
hasOfferCatalog Optional Mittel Listet angebotene Versicherungsarten auf
aggregateRating Optional Sehr hoch (wenn vorhanden) Bewertungssterne im SERP — nur mit echten Rezensionen auf der Seite
areaServed Optional Mittel Definiert das Einzugsgebiet: City, State oder GeoShape
geo Optional Mittel GPS-Koordinaten für Google Maps-Einbindung
sameAs Optional Mittel Social-Media-Profile, Google My Business — stärkt E-E-A-T
description Optional Mittel Kurze, präzise Beschreibung der Dienstleistungen
priceRange Optional Niedrig Bei Versicherern oft weggelassen (Preise variieren stark)

areaServed: Das Einzugsgebiet korrekt definieren

Für Versicherungsvermittler, die regional tätig sind, ist areaServed besonders interessant. Du kannst das Einzugsgebiet auf verschiedene Arten definieren:

Option 1: Einzelne Stadt

"areaServed": {
  "@type": "City",
  "name": "Köln"
}

Option 2: Mehrere Städte als Array

"areaServed": [
  {"@type": "City", "name": "Köln"},
  {"@type": "City", "name": "Bonn"},
  {"@type": "City", "name": "Leverkusen"}
]

Option 3: Bundesland

"areaServed": {
  "@type": "State",
  "name": "Nordrhein-Westfalen"
}

Option 4: Postleitzahlen-Gebiet (GeoShape)

"areaServed": {
  "@type": "GeoCircle",
  "geoMidpoint": {
    "@type": "GeoCoordinates",
    "latitude": 50.9382,
    "longitude": 6.9525
  },
  "geoRadius": "50000"
}

Der geoRadius-Wert wird in Metern angegeben. 50.000 Meter entsprechen einem Einzugsgebiet von 50 km rund um den Standort. Mehr dazu im Artikel über ServiceArea Schema Markup.

Versicherungsfilialen: Schema für Ketten und Mehrfach-Standorte

Wenn du für mehrere Standorte (z.B. verschiedene Filialen desselben Versicherungsbüros) Schema Markup erstellst, empfiehlt sich für jede Standortseite ein eigenes Schema-Objekt. Verwende branchOf, um die Filiale mit der Hauptorganisation zu verknüpfen:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "InsuranceAgency",
  "name": "Versicherungsbüro Maier & Partner — Filiale Bonn",
  "url": "https://www.versicherung-maier.de/filiale-bonn",
  "telephone": "+49 228 111222333",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "Münsterplatz 5",
    "postalCode": "53111",
    "addressLocality": "Bonn",
    "addressCountry": "DE"
  },
  "openingHours": ["Mo-Fr 09:00-18:00"],
  "branchOf": {
    "@type": "InsuranceAgency",
    "name": "Versicherungsbüro Maier & Partner",
    "url": "https://www.versicherung-maier.de"
  }
}
</script>

Bewertungen richtig einbinden: aggregateRating für Versicherungsmakler

Bewertungssterne in den Suchergebnissen sind für Versicherungsmakler besonders wertvoll — sie schaffen Vertrauen in einer Branche, der Kunden oft mit Skepsis begegnen. Damit aggregateRating als Rich Snippet erscheint, müssen folgende Bedingungen erfüllt sein:

  1. Die tatsächlichen Kundenbewertungen müssen auf der Seite sichtbar sein (nicht nur im Schema verankert)
  2. Der ratingValue muss zwischen 1 und 5 liegen (oder dem definierten bestRating)
  3. Die Bewertungen dürfen nicht selbst verfasst oder manipuliert sein (Google's Policy)
  4. Mindestens eine Bewertung muss vorhanden sein (reviewCount ≥ 1)
"aggregateRating": {
  "@type": "AggregateRating",
  "ratingValue": 4.8,
  "reviewCount": 73,
  "bestRating": 5,
  "worstRating": 1
}

Vorsicht bei gefälschten Bewertungen

Google kann manipulierte Bewertungsdaten im Schema erkennen und penalisieren. Verwende aggregateRating nur, wenn du echte Kundenbewertungen auf deiner Seite anzeigst — z.B. eingebettete Google-Bewertungen oder ein eigenes Bewertungswidget.

Häufige Fehler bei InsuranceAgency Schema

1. FinancialService statt InsuranceAgency verwenden

Viele Versicherungsmakler verwenden den allgemeinen Typ FinancialService, weil er leichter zu finden ist. Der spezifischere Typ InsuranceAgency ist aber besser, weil er Google genauere Informationen über die Branche des Unternehmens liefert.

2. Öffnungszeiten-Format falsch

Korrekt: "Mo-Fr 09:00-18:00" (Schema.org-Format)
Falsch: "Montag bis Freitag, 9 bis 18 Uhr" oder "Mon-Fri 9am-6pm"

3. Schema nur auf der Startseite

Viele Versicherungsmakler platzieren das Schema nur auf der Startseite. Besser: Einbinden auf jeder wichtigen Seite, die das Unternehmen beschreibt — Kontaktseite, Über-uns-Seite, und ggf. auf Produktseiten mit spezifischen Dienstleistungen.

4. Telefonnummer ohne Landesvorwahl

Korrekt: "+49 221 9876543"
Falsch: "0221 9876543" (ohne internationale Vorwahl kann Google die Nummer nicht eindeutig einem Land zuordnen)

5. Kein addressCountry

Die Property addressCountry: "DE" wird oft vergessen. Sie ist entscheidend für die lokale Suche — ohne sie kann Google dein Unternehmen nicht sicher einem Land zuordnen.

Schema validieren: So prüfst du dein Markup

Nach der Implementierung solltest du das Schema mit diesen Tools validieren:

  • ☐ Google Rich Results Test: Prüft, ob das Schema für Rich Results qualifiziert und zeigt Fehler/Warnungen an. (search.google.com/test/rich-results)
  • ☐ Schema.org Validator: Prüft die technische Korrektheit der JSON-LD-Struktur. (validator.schema.org)
  • ☐ JSON-LD Validator: Prüft die JSON-Syntax auf Fehler (fehlende Kommas, Anführungszeichen etc.). Nutze unseren JSON-LD Validator.
  • ☐ Google Search Console: Überwacht erkannte strukturierte Daten und zeigt Fehler in der Sektion "Verbesserungen".

InsuranceAgency Schema und Google My Business: Synergien nutzen

Viele Versicherungsmakler unterschätzen die Verbindung zwischen Google My Business (GMB) und Schema Markup. Beide Systeme ergänzen sich:

  • GMB liefert das lokale Knowledge Panel, Bewertungen und Maps-Einträge
  • Schema Markup liefert strukturierte Daten für organische Suchergebnisse und verknüpft die Website mit dem GMB-Eintrag
  • Optimal: GMB-URL als sameAs-Property einbinden und sicherstellen, dass Name, Adresse und Telefon (NAP) in beiden Systemen identisch sind

NAP-Konsistenz ist einer der wichtigsten lokalen SEO-Faktoren. Mehr dazu im Artikel NAP-Konsistenz für lokales SEO.
