Lazy Loading für Bilder: Was du wissen musst

⚡

Was ist Lazy Loading?

Das loading="lazy"-Attribut weist den Browser an, ein Bild erst zu laden, wenn es in den sichtbaren Bereich scrollt. Das reduziert die initiale Seitenladezeit erheblich — besonders auf Seiten mit vielen Bildern. Browser unterstützen es seit 2019 nativ.

⛔

Hero-Bild NIEMALS lazy laden

Das erste große Bild einer Seite ist fast immer der LCP-Kandidat (Largest Contentful Paint). Wird es lazy geladen, verzögert sich der LCP — ein direkter Google-Ranking-Faktor. Das Tool markiert das erste Bild automatisch als potenziellen LCP-Kandidaten.

✅

Richtige Verwendung

Faustregel: Alle Bilder unterhalb des Falzes (below the fold) sollten loading="lazy" nutzen. Das erste sichtbare Bild (Hero, Logo, CTA-Bild) bekommt loading="eager" oder gar kein Loading-Attribut (Browser-Standard ist eager). Lies unseren vollständigen Lazy-Loading-Guide.

📊

Auswirkung auf Core Web Vitals

Lazy Loading reduziert die Netzwerk-Anfragen beim Seitenlade — das verbessert den LCP (wenn richtig angewandt) und den FCP. Falsch angewandtes Lazy Loading (auf LCP-Kandidaten) verschlechtert den LCP dagegen messbar. Prüfe die Core Web Vitals nach einer Optimierung.

Korrekte Implementierung

✅ Hero-Bild (LCP-Kandidat)

<img
  src="hero.webp"
  alt="Hauptbild Beschreibung"
  width="1200"
  height="600"
  loading="eager"
  fetchpriority="high"
>

✅ Bilder below the fold

<img
  src="produkt-1.webp"
  alt="Produktbild Beschreibung"
  width="400"
  height="300"
  loading="lazy"
>

❌ Häufigster Fehler: LCP-Kandidat lazy geladen

<img src="hero.webp" alt="Hero" loading="lazy">  <!-- FALSCH: verzögert LCP! -->
