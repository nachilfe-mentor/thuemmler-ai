    💡 Protokoll im Browser direkt prüfen

    Da Browser-Sicherheitsrichtlinien das Auslesen mancher HTTP-Header von anderen Domains einschränken, ist die direkteste Methode:

    1. Öffne die URL im Browser → Rechtsklick → "Untersuchen" (DevTools)
    2. Klicke auf den Tab "Netzwerk" (Network)
    3. Lade die Seite neu (F5)
    4. Klicke auf den ersten Request (HTML-Dokument)
    5. Unter "Header" → "Allgemein" siehst du das Protokoll (h2, h3, HTTP/1.1)

    Alternativ: Rechtsklick auf Spaltenheader im Network-Tab → "Protokoll" aktivieren, um das Protokoll für alle Requests zu sehen.

    HTTP/2 und HTTP/3: Was du wissen musst

    HTTP/1.1
    • • Ein Request pro TCP-Verbindung
    • • Head-of-Line Blocking
    • • Unkomprimierte Header
    • • Browser nutzt 6 parallele Verbindungen als Workaround
    • → Langsamer, mehr Overhead
    HTTP/2 (h2)
    • • Multiplexing: viele Requests gleichzeitig
    • • HPACK Header-Komprimierung
    • • Binäres statt Textprotokoll
    • • Server Push (selten genutzt)
    • → 2-3× schneller als HTTP/1.1
    HTTP/3 / QUIC (h3)
    • • UDP statt TCP
    • • 0-RTT-Verbindungsaufbau
    • • Kein Head-of-Line Blocking
    • • Besser bei Paketverlust (Mobilfunk)
    • → Beste LCP auf mobilen Netzwerken

    SEO-Relevanz: Warum HTTP/2 & HTTP/3 wichtig sind

    Das HTTP-Protokoll beeinflusst direkt deine Core Web Vitals — insbesondere LCP (Largest Contentful Paint) und TTFB (Time to First Byte). Google nutzt CWV als Ranking-Faktor. Websites auf HTTP/1.1 laden durchschnittlich 2-3× langsamer als HTTP/2-Sites, weil Browser serielle Anfragen stellen müssen. Für gute Core Web Vitals ist HTTP/2 heute Mindeststandard — HTTP/3 ist besonders für Mobile-Traffic relevant.

    HTTP/2 aktivieren (je nach Server)

    Nginx
    server { listen 443 ssl http2; ... }
    Apache
    Protocols h2 h2c http/1.1
    LoadModule http2_module modules/mod_http2.so
    Cloudflare / CDN
    HTTP/2 ist automatisch aktiv (kein Setup nötig)
