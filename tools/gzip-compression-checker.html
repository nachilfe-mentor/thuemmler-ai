Prüfe ob deine Website Gzip oder Brotli-Komprimierung aktiviert hat. Komprimierung reduziert die Dateigröße um bis zu 80 % und ist ein direkter Ranking-Faktor für Page Speed.

Wie dieser Check funktioniert

Dieser Checker ruft deine URL über einen CORS-Proxy ab und analysiert den Content-Encoding-Response-Header. Dieser Header teilt dem Browser mit, in welchem Format die Antwort komprimiert wurde. Außerdem wird die Antwortgröße geschätzt, um den Komprimierungsvorteil zu illustrieren.

Warum HTTP-Komprimierung für SEO wichtig ist

⚡

Page Speed

Gzip komprimiert HTML, CSS und JavaScript um 60–80 %. Kleinere Dateien = schnellere Ladezeiten = besseres Ranking.

📊

Core Web Vitals

Komprimierung verbessert direkt LCP (Largest Contentful Paint) und TTFB (Time to First Byte) — beides Google-Rankingfaktoren.

💰

Bandbreite sparen

Weniger übertragene Bytes bedeuten geringere Hosting-Kosten und schnelleres Laden auf mobilen Verbindungen.

Gzip vs. Brotli: Was ist der Unterschied?

Merkmal Gzip Brotli
Kompressionsrate Gut (60–70 %) Besser (70–80 %)
Browser-Support Universell (alle Browser) 95 %+ moderne Browser
Server-Unterstützung Alle Server Nginx 1.11+, Apache 2.4.26+
CPU-Last Gering Etwas höher
Empfehlung Fallback für ältere Clients Primär wenn möglich

Gzip für verschiedene Server aktivieren

Apache (.htaccess)

<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html
  AddOutputFilterByType DEFLATE text/css
  AddOutputFilterByType DEFLATE text/javascript
  AddOutputFilterByType DEFLATE application/javascript
  AddOutputFilterByType DEFLATE application/json
</IfModule>

Nginx (nginx.conf)

gzip on;
gzip_types text/html text/css application/javascript application/json;
gzip_min_length 1024;
gzip_comp_level 6;

Brotli (Nginx mit ngx_brotli Modul)

brotli on;
brotli_types text/html text/css application/javascript application/json;
brotli_comp_level 6;
